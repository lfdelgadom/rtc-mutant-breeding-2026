Block 1

Prediction, not explanation

Two different questions

Classical statistics Machine learning
Goal Explain, estimate effects, test Predict new observations
Data Designed trials, few variables More variables than samples
Model Specified from the design Learned from the data
Output Effects with uncertainty A prediction and its error
Main risk Wrong model structure Overfitting, no transfer

They are not rivals: the design and the mixed model give clean phenotypes; ML turns cheap measurements into predictions of expensive ones.

Where it pays in a breeding programme

Application Predictors Target
Chemical composition NIR spectra Protein, oil, starch, carotenoids
Disease and vigour Image features (Day 4) Severity, biomass
Yield and traits Drone and sensor indices Yield, height
Genomic prediction Thousands of markers Breeding value
G×E prediction Environmental covariates Performance in a new environment

In a mutation breeding programme

  • M2 and M3 populations have thousands of plants: the laboratory cannot measure them one by one
  • A prediction from an image or a spectrum ranks every plant
  • The laboratory measures only the promising ones

The prediction does not replace the measurement. It decides where to spend it.

Block 2

The data: NIR spectra of cassava

A real data set from the CIAT cassava programme

  • Part of a large calibration database to predict carotenoids in fresh cassava roots (Davrieux et al. 2016)
  • The laboratory method (HPLC) analyses only a few samples per day; NIR is cheap and fast
  • Spectra from 400 to 2498 nm every 2 nm: 1050 variables
  • 200 calibration samples (2009 to 2012) and 80 test samples (2013)

More variables than samples: a standard multiple regression cannot be fitted.

The spectra

The spectra look alike: the information is in small differences.

The population is evolving

The test year has a mean of 8.5; the calibration years have 5.6. The next season is not like the previous ones.

Preparing the spectra

  • SNV: subtract the mean of each spectrum and divide by its standard deviation (removes level and scale)
  • First derivative after light smoothing (removes the baseline slope, sharpens peaks)
  • Applied to each spectrum separately: no information from other samples

Block 3

The models and how they perform

Measuring prediction quality

On samples the model has not seen:

  • RMSE: typical error, in the units of the trait
  • R² of the prediction
  • Bias: mean of (prediction minus observed), should be near 0
  • RPD: standard deviation of observed values divided by RMSE (above 2: useful for screening)

Always compare with a baseline: predict the calibration mean for every new sample. Here the RMSE of the baseline is 4.76.

The model families

Model Idea Tuning
Ridge Linear, shrinks all coefficients Amount of shrinkage
Lasso Shrinks, sets many coefficients to 0 Amount of shrinkage
Elastic net Mix of ridge and lasso Shrinkage and mix
PLS Few components that covary with the trait Components
Random forest Average of many trees Variables per split
Boosting Trees built one after another Trees, rate, depth
SVM Flexible curve, margin of tolerance Cost, kernel width

Tune by cross-validation inside the calibration set, never with the test set.

One function to fit them all

fit_predict <- function(model, A, y, B) {
  switch(model,
    PLS   = { ... plsr(y ~ X, ncomp = 15, validation = "CV") ... },
    Lasso = { cv <- cv.glmnet(A, y, alpha = 1);   predict(cv, B, s = "lambda.min") },
    ENet  = { cv <- cv.glmnet(A, y, alpha = 0.5); predict(cv, B, s = "lambda.min") },
    RF    = { predict(ranger(x = A, y = y, num.trees = 500), B)$predictions },
    GBM   = { ... gbm(..., cv.folds = 5) ... },
    SVM   = { tu <- tune.svm(A, y, gamma = 10^(-4:-2), cost = c(1, 10, 100)); predict(tu$best.model, B) })
}
pred_test <- sapply(models, function(m) fit_predict(m, A, yA, B))

Block 4

Honest validation and data leakage

Three sets, three roles

Set Used for Rule
Training Fit the model Many samples
Validation / CV folds Choose tuning and the model Taken from the training data
Test Report the final error Used once, at the end

The way you split must follow the question: new year, split by year. New genotype, split by genotype. New location, split by location.

Random against by-year validation

The error for a new year is 75 % larger than random cross-validation reports: samples of the same year share conditions that the model learns.

Data leakage

Information from validation or test samples reaches the model before the evaluation. The error looks smaller than it is.

  • The same genotype, plant or sample (or replicates) in training and test
  • Choosing variables (wavelengths, markers) with all the data, then cross-validating only the model
  • Scaling or transforming with means computed on all samples
  • Tuning on the test set and reporting the same test set
  • A predictor that is a consequence of the target

Every step that learns something from the data belongs inside the validation loop.

Wrong and right

# WRONG: variables chosen with all the samples
top <- order(-abs(cor(A, yA)))[1:30]
cv_error_wrong <- cross_validate(model, A[, top], yA)

# RIGHT: inside each fold, choose with the training part only
for (k in 1:10) {
  train <- fold != k
  top <- order(-abs(cor(A[train, ], yA[train])))[1:30]
  fit <- fit_model(A[train, top], yA[train])
  pred[!train] <- predict(fit, A[!train, top])
}

Block 5

When the next season is different

A calibration is a living tool

With no new sample the error is 1.52. Adding 20 laboratory measurements of the new year: 1.14. Check each season with a few reference samples and update.

The same workflow for other data

  • Image features (Day 4): area, colour indices, shape as predictors; a visual or laboratory score as the target
  • Markers: ridge is the model behind GBLUP; validate by genotype and by environment
  • G×E: predicting a new environment needs a description of it (soil, weather); without covariates, use the mean of the line
  • Early generations: predictions on thousands of M2 plants, then a check of the best ones

Block 6

Limits, the breeder, exercise

Limitations

  • Small data sets: the error estimate is itself uncertain; prefer simple models
  • Overfitting: more flexible models understate the real error
  • Interpretability: forests and boosting do not give effects to explain
  • Transfer: other crop, season, instrument or laboratory needs a new check
  • Label quality: noisy laboratory values limit the best possible prediction

ML does not know the biology. The breeder knows if a prediction makes sense, which samples are unusual and which errors matter.

Exercise

Use the cassava data.

  1. Calibration: samples of 2009 to 2011. Validation: samples of 2012
  2. Fit PLS and the elastic net; compute RMSE and bias on 2012
  3. Compare with random 10-fold cross-validation inside 2009 to 2011

Which error would you report as the expected error for next season?

Key takeaways

  • ML is for prediction: cheap measurements into estimates of expensive ones
  • Always compare with a baseline; there is no best model in general
  • The honest error comes from data the model never saw, split the way the model will be used
  • Avoid leakage: every learning step belongs inside the validation loop
  • A calibration drifts: update it every season with a few reference samples
  • The breeder decides; the prediction ranks and prioritizes
